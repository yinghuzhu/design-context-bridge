# 输入契约与有界分析

## 开始门禁

在读取目标仓库实现前，从当前用户、适用项目说明或 `.figma-context/` 确认以下输入；来源冲突时先请用户裁决：

- `Figma URL`：本次目标对应的设计节点。
- `target directory`：要修改的目标仓库或目录。
- `target page/route`：本次创建或迁移的页面、路由或明确入口。
- 迁移任务的 `approved completed new references`：已完成且可作为新版规范的页面；`initial` 模式允许但必须明确为空，其他迁移模式至少明确一个，而不是由 Agent 猜测。
- 迁移任务的 `protected business behavior`：必须保持的 API、路由、状态、校验、错误处理、交互或业务流程；确实没有时也要明确为无。

项目说明包括适用的 `AGENTS.md`、`CLAUDE.md`、README、测试说明及用户直接指定的文档。已由这些来源或 `.figma-context/` 明确且没有冲突的事实，无需用户重复提供。输入缺失时先询问，且不得扫描或修改目标仓库。

## 范围角色

把进入范围的对象显式归入一个角色：

- `target`：本次要实现的页面、路由和直接实现文件。
- `approved_reference`：由用户、项目说明或 `.figma-context/` 明确批准的已完成新版页面。
- `legacy_behavior_source`：只用于继承目标页既有业务语义的旧实现。
- `protected`：不得改变的文件、组件、接口或业务流程。
- `unknown`：来源与角色尚未确认的对象。

只有前四类可以影响实现。`unknown` 不得作为视觉规范、复用依据或业务决策依据，需澄清或忽略；只有需要它才能继续时才向用户询问。

## 允许的依赖闭包

输入范围明确后，只读取完成当前目标所需的：

- 用户命名的 `named routes/files`，以及定位该路由入口所必需的最小路由配置；
- 目标实现直接引用的 `direct components`；
- 已批准的 `approved refs`，以及其中可能复用于目标的 `reusable direct dependencies`、共享样式和素材；
- 与目标业务行为直接相关的 `API/store/validation/tests`；
- 为确认上述对象语义而必须继续追踪的一层直接依赖。

Agent 不要求用户预先列出每个文件。范围明确后，先定向定位入口和必要依赖，再提出具体文件和组件映射供确认。

## 停止规则

- 禁止默认遍历全部页面、完整组件库或全部 Git 历史。
- 禁止按名称、时间、目录结构或提交记录猜测哪些页面属于新版。
- 禁止为了建立全仓索引而读取范围外文件；不要默认启动全部服务。
- 信息满足当前迁移后立即停止。
- 新发现若会扩大目标、参考或保护边界，先请求确认，不得自行扩展范围。
